### Discord Bot が動かない問題のデバッグ

#### 問題の症状

- Discord Botはオンライン状態になるが、DMやメンションに反応しない
- Admin UIの「Pending Pairing Requests」にも何も表示されない

#### 根本原因の特定

1. **コンテナが起動していなかった**
   - `/debug/container-config` で `Container service disconnected` エラー
   - Cloudflare Sandboxコンテナはコールドスタートで、最初のリクエストで起動する

2. **`groupPolicy: "allowlist"` だが `guilds` 設定がなかった**
   - R2バックアップから復元された設定に `groupPolicy: "allowlist"` が含まれていた
   - `allowlist` モードでは許可するサーバーを明示的に指定する必要がある
   - `guilds` 設定がなかったため、全サーバーが拒否されていた

#### 解決策

`start-moltbot.sh` を修正して、Discord設定時に以下を追加:
- `delete config.channels.discord.groupPolicy;` で制限を削除
- `config.channels.discord.guilds = { '*': { requireMention: true } };` で全サーバーを許可

### Moltbotのペアリングメカニズム

#### 2種類のペアリング

| 種類 | 対象 | コマンド |
|------|------|----------|
| デバイスペアリング | CLI、WebSocket | `clawdbot devices approve <requestId>` |
| チャンネルペアリング | Discord、Telegram | `clawdbot pairing approve <channel> <code>` |

Admin UIは「デバイスペアリング」のみ対応。Discordのペアリングは別コマンドが必要。

#### ペアリング承認の実行方法

Cloudflare Workers環境では `/debug/cli` エンドポイントを使用:
```
/debug/cli?cmd=clawdbot%20pairing%20approve%20discord%20<CODE>
```

### Cloudflare AI Gateway vs 直接API接続

#### AI Gateway経由の問題

- 「Authenticated Gateway」がONの場合、Gateway自体の認証トークンが必要
- APIキーのパススルー設定が正しくないと `invalid x-api-key` エラー

#### 直接接続への切り替え

AI Gatewayを使わない場合:
```bash
# AI Gateway関連を削除
npx wrangler secret delete AI_GATEWAY_BASE_URL
npx wrangler secret delete AI_GATEWAY_API_KEY

# 直接APIキーを設定
npx wrangler secret put ANTHROPIC_API_KEY
```

### Cloudflare Workersデプロイ時のDocker設定

Docker DesktopのパスがシェルのPATHに含まれていない場合:
```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
export WRANGLER_DOCKER_BIN="/Applications/Docker.app/Contents/Resources/bin/docker"
npm run deploy
```

## メモ

- Gatewayを再起動すると、チャンネルペアリングもリセットされる（毎回承認が必要）
- `dm.policy: "allowlist"` と `allowFrom` でユーザーIDを指定すれば、ペアリング不要にできる
- Dockerfileの `# Build cache bust:` コメントを更新することでイメージの再ビルドを強制できる
- R2バックアップから設定が復元されるため、新しい設定を適用するには `start-moltbot.sh` で明示的に上書きする必要がある
